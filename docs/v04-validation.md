# S2G 0.4 色彩控制与验证

2026-10-11。本次在原有风格基础上增加独立的色彩控制；GR 风格仍未通过同场景 Ricoh 数据拟合。

## 行为

| 控制 | 范围／默认 | 作用 |
| --- | --- | --- |
| 饱和度 | -100～100／0 | 在 Oklab 中缩放色度；-100 为黑白。整体控制，不自动保护肤色。 |
| 自然饱和度 | -100～100／0 | 较淡的颜色获得更大调整权重；宽暖色区获得较低权重。肤色保护是启发式，没有人脸或肤色识别。 |
| 冷暖分离 | 0～200%／100% | 单独缩放风格的阴影／高光 tint，不同时改变曝光、曲线、矩阵或风格强度。中性风格／零风格强度不产生分离色调。 |

饱和度和自然饱和度位于原风格显示转换后、颗粒前。sRGB 解码 → Oklab → 色度调整 → 固定 Oklab L／h 的色度二分收缩 → sRGB 编码。只有越界像素参与 16 次二分搜索，处理不使用全图统计，保持预览、分块和导出的一致性。感知明度与色相保持有浮点误差和最终剪切的边界；纯灰色的色相没有定义。

参数位于 `resources/color_controls_v1.json`，实现位于 `color_controls.py`。关闭新控制时直接返回旧渲染结果，不增加 Oklab 往返量化误差。冷暖分离使用原有 V1/V2 tint 结构，默认倍率时不增加运算。

旧参数缺少新字段时采用 0／0／100 默认值。新字段处于默认值时，序列化省略它们，继续使用 0.2.0 或 0.3.0 渲染身份；只有非默认控制才记录 0.4.0、基础渲染版本及独立控制参数 SHA-256。旧预设载入前在界面补齐默认字段。没有修改原片或用户已保存的 sidecar。

## 验证

60 项完整测试通过，含真实 `DSC00944.ARW`。新增覆盖：灰阶与明度保持、黑白模式、自然饱和度权重、肤色保护、超色域颜色的色相保持、极端滑块值、分块独立性、参数验证、sidecar 版本与哈希、JPEG／TIFF 重复导出和 8／16 位量化一致性。

`DSC00914.ARW` 与 `DSC00944.ARW` 各重渲染正片／负片 V1/V2，8 张默认结果与 0.3 的对应 JPEG SHA-256 完全一致。新调整样片设置为正片 V2、82% 强度、饱和度 +12、自然饱和度 +35、冷暖分离 130%、原拍摄白平衡；没有额外曝光和颗粒。图片、源／输出哈希和编辑参数位于 `output/v04-validation`。这些是操作示例，不是拟合得到的 GR 配方。

网页完成滑块更新及批量导出检查，实际 TIFF 和截图记录在 `output/v04-ui-validation`。原 `DSC00944.ARW.s2g.json` 的 SHA-256 仍为 `061a7be443bba044049d1fbd27ee8b83a227c584b3b069758ad766518c807c8c`。

CLI 同样支持 `--saturation`、`--vibrance`、`--split-toning`，例如：

```powershell
& .venv/Scripts/python.exe tools/run.py develop samples/DSC00944.ARW --look gr_positive_experimental_v2 --saturation 12 --vibrance 35 --split-toning 130 --max-size 1600 --output output/my-color-adjustment.tif
```

颜色偏淡的照片可先调整自然饱和度，再逐步调整整体饱和度。原片曝光、白平衡与色彩控制相互独立；本次没有增加自动曝光或声称提高 GR 相似度。
