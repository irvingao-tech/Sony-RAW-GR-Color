# 0.2 本地编辑器验证

日期：2026-10-11（Asia/Shanghai）。当前交付可运行的浏览器编辑器原型，不将实验风格视为已经完成参考拟合。

## 已实现

- 完整解码的未缩放相机 RGB；LibRaw 处理黑电平后，由共享浮点图完成白平衡、相机矩阵、XYZ 与 ACEScg 转换。
- 明确使用 Bradford 将 D65 适应到 ACES 白点；矩阵和参数文件有版本与 SHA-256。
- 中性、正片实验版、负片实验版；两种风格采用独立曝光、单调对数亮度曲线、饱和度、黑位与冷暖参数。
- 曝光、近似色温、色调、高光、阴影、种子单色颗粒、居中比例裁切、90° 步进旋转。
- 共享渲染图的预览 / 导出、原图按住对比、RGB 直方图。
- sidecar 保存 / 读取、引擎与参数哈希校验、SQLite 照片库 / 预设 / 导出任务记录。
- sRGB JPEG、带标准 sRGB ICC 的 16 位 TIFF、导出尺寸、批量队列、取消、逐文件错误报告。
- 固定 loopback 本机服务、会话令牌与同源校验；项目目录外的路径不参与处理。

## 自动化验证

40 项测试全部通过，其中包含 5 项真实 A7C II 样本测试。依赖完整性检查通过。

- Bradford 白点转换、相机中性轴与 AP1 输出中性轴正确。
- 场景线性矩阵保留负值和大于 1 的值；显示亮度曲线单调。
- 风格强度为零时与中性像素完全一致。
- 固定种子颗粒重复一致；改变种子会改变像素。
- 裁切后的顺时针旋转符合预期；8 / 16 位渲染使用相同曲线数学。
- sidecar 往返保留编辑；错误源文件、配置哈希或引擎版本不会静默接受。
- JPEG / TIFF 嵌入对应 ICC；真实 ARW 在固定参数下重复导出两个格式得到相同文件哈希。
- 源文件不变；已有输出保护；取消时不发布；批量单项失败不会阻止下一张。
- Windows 下 SQLite 连接在每次事务后关闭，测试目录可以正常回收。

预览最初尝试 LibRaw 半尺寸解码，但它在细节处和完整 AHD 解码存在差异。现已改为完整解码后缩小缓存。真实 `DSC00944.ARW` 在相同 1400 长边、相同几何与参数下，缓存预览与从完整像素渲染的结果逐像素一致。

## 界面验证

通过本地浏览器界面实际检查：照片载入、正片 / 负片切换、曝光滑块、1:1 裁切、保存参数和 TIFF 导出。已检查常规桌面布局与窄面板布局。

使用 `DSC00944.ARW` 保存的验证参数为正片实验版、强度 0.82、曝光 0、拍摄白平衡、无裁切 / 旋转 / 颗粒。sidecar 为 `samples/DSC00944.ARW.s2g.json`。

界面导出的验证 TIFF：`output/ui-validation/DSC00944-positive.tif`，形状 (1067, 1600, 3)，uint16，ICC 为标准 sRGB。源文件 SHA-256 仍为 `961dd7a2f7cf4912389176c2cba1d36e942f8430b5c01e30741b7e8bf3d54371`。

已生成 1600 长边的实验风格 JPEG：`output/DSC00944-positive-v02.jpg` 和 `output/DSC00944-negative-v02.jpg`。暖缓存预览在界面检查中约 200–350 ms；这些是当前机器和单张照片的观察值，不是参考硬件基准。

## 架构和剩余工作

界面目前是无第三方前端依赖的本地 HTML / CSS / JavaScript，Python 标准 HTTP 服务为薄接口，共享 NumPy 渲染图为像素处理权威。此方案优先交付可试用的本地流程；规范建议的 Tauri / React / Rust 外壳和 Windows 安装程序尚未实现。

M1 的实测相机配置和色卡报告、理光参考数据拟合、镜头校正、Display P3、GPU、任意拖拽裁切、评级 / 色标、LUT 导出、完整工作集与兼容性评估仍待完成。

色温采用 Planckian-locus 近似，显示图是自定义 SDR 渲染，不宣称为官方 ACES Output Transform。源传感器已剪切的高光无法恢复。只有整数照片解码到浮点的后续变换保留超范围值。
